# 游戏10003 - 算24点

## 概述

游戏10003是一款多人实时抢答的算24点对战游戏。系统每局发放4个数字，玩家用加减乘除（允许括号和分数中间结果）组成算式等于24，第一个提交正确答案的玩家直接赢得本局。

- **游戏ID**: 10003
- **人数**: 2~6人（匹配 dynamic 2~6人，私人房最多6人）
- **局数**: 匹配房固定1局；私人房创建时可选 **3/5/7局**（`privateRule.playNum`）
- **发牌数字范围**: 可配置，默认 1~9（`config.NUMBER_RANGE`），服务端保证每组数字有解
- **每局答题时间**: 默认30秒（`config.ROUND_TIME`），超时无人答对则本局无胜者

## 玩法规则

1. 每局开始服务端随机生成4个数字（用24点求解器校验保证有解）并广播给所有玩家
2. 玩家提交算式字符串，支持 `+ - * /`、括号、一元负号、多位数
3. 服务端校验规则（`expression.lua`）：
   - 结果必须**恰好等于24**（使用分数精确运算，支持 `8/(3-8/3)=24` 这类分数中间结果）
   - 表达式中的数字集合必须与发牌数字**完全一致**（每个数字恰好用一次，不允许其他数字）
4. 错误提交：可无限重试，广播给所有玩家但不计名次
5. **第一个答对的玩家直接结束本局**（答对者 rank=1，其余玩家 rank=0，无倒计时无第二名）
6. 答对后该玩家本局不能再提交

## 单局生命周期

```
START(1秒) ──发牌(4个数字+时限广播)──▶ PLAYING(默认30秒) ──▶ END
                                         │
                    ┌── 玩家 submitAnswer：解析 → 分数求值 → 数字集合校验
                    │    错误 → 广播 answerResult{correct=0}，可重试
                    │    正确 → 锁定玩家 + 广播 answerResult{correct=1,rank=1}
                    │    └─▶ 立即结束本局（END）
                    └── 超时无人答对 → endType=TIMEOUT，全员 rank=0
```

- **END阶段**：组装排名（答对者含算式/用时/rank，未答对 rank=0）→ `gameResult` 计分 → 广播 `gameEnd` → `onGameEnd`
- **私人房**：`playedCnt < mode.maxCnt` 时进入 HALFTIME（全员回到 ONLINE，再次准备后开下一局），满局后 `roomEnd`（发 totalResult、玩家状态回 ONLINE、通知 gameManager 销毁）
- **匹配房**：1局结束后直接 `roomEnd`
- 每局开始时 `logicHandler.init` 完全重置状态

## 计分规则（参考10002）

### 匹配模式（1局，`scoring.lua calculateMatchScore`）
- 答对者（rank=1）：`delta = playerCnt - rank + 1 = playerCnt`，直接加到战力（cp）
- 未答对者：按当前战力分档扣分（`config.SCORING.MATCH.unfinished_penalty`，0~3分）
- 额外累加每日积分 Redis zset `game10003DayRank`（答对者 +`playerCnt-rank+1`）

### 私人房（3/5/7局，`scoring.lua calculatePrivateScore`）
- 每局答对者 +`playerCnt - rank + 1 = playerCnt` 分，累计到 `totalScores`
- 所有局结束后按总分排名，下发 `totalResult`

| AI.ACTION_PROBABILITY | 60 | AI提交概率（百分比） |
| AI.SUBMIT_DELAY | 2~8 | AI提交延迟区间（秒） |

### `src/services/games/10003/configLogic.lua`

- `GAME_STEP`: START(1) / PLAYING(2) / END(3)
- `STEP_TIME_LEN`: START=1秒，PLAYING=30秒（每局init时被maxTime覆盖），END=0秒
- `END_TYPE`: WIN(1) 有人答对 / TIMEOUT(2) 超时无人答对
- `TARGET_VALUE`: 24

### 匹配配置 `src/services/match/matchConfig.lua`

- `[10003]` 队列1：dynamic 2~6人，rateDiff=500；队列2：dynamic 2~4人，rateDiff=800；队列3/4 使用默认配置

## 核心模块

| 模块 | 文件 | 职责 |
|------|------|------|
| 表达式校验 | `expression.lua` | 分词、递归下降解析、分数精确四则运算（gcd约分、除零处理）、结果=24校验、数字集合严格比对；不依赖skynet，可独立测试 |
| 24点求解器 | `solver.lua` | 枚举所有括号组合求目标值，返回算式；供发牌有解校验与AI解题 |
| 单局逻辑 | `logic.lua` | 阶段状态机（START→PLAYING→END）、发牌、submitAnswer校验与广播、排名、重连补发状态、超时驱动 |
| 房间 | `room.lua` | 继承PrivateRoom，房间生命周期、计分（匹配cp/私房总分）、每日积分、totalResult |
| AI | `ai.lua` | 收到发牌后用求解器解题，随机延迟2~8秒、60%概率提交 |
| 计分 | `scoring.lua` | 与10002相同（calculateMatchScore / calculatePrivateScore） |

## 重连流程

PLAYING阶段断线重连时，服务端向该玩家补发（`logicHandler.relink`）：
1. `gameRelink` + `stepId` + `gameStart`(brelink=1)
2. 本局4个数字（`dealCards`）
3. 已发生的答对提交（`answerResult`）
4. PLAYING阶段剩余答题时间（`gameClock`）

## AI行为

1. 收到PLAYING阶段消息后，通过 `roomHandlerAi.getDealNumbers()` 获取本局数字并用求解器求解
2. 有解则按 `AI.ACTION_PROBABILITY`（默认60%）决定是否提交
3. 提交前随机延迟 `AI.SUBMIT_DELAY`（默认2~8秒），保证真人玩家有抢答空间
4. 提交前再次检查阶段，避免本局已结束时机器人仍提交

## 创建房间示例

## 数据库表

房间日志和结算日志按游戏ID动态写入（`dbLog.lua`），上线前需按 `dbLog.lua` 中的模板在 gamelog 库创建：

```sql
CREATE TABLE `logRoom10003` ( ... );   -- 参照 logRoom10001 模板
CREATE TABLE `logResult10003` ( ... ); -- 参照 logResult10001 模板
```

每日积分排行榜使用 Redis zset（`game10003DayRank:YYYYMMDD`，有效期7天），无需建表。

## 与10002/10001的差异

- 相比10002：无道具、无地图/消除，改为提交算式抢答；本局结束条件为**第一个答对立即结束**（无倒计时）
- 相比10001：支持2~6人（非固定2人）；计分参考10002（匹配cp制+每日积分，私房总分制）
- 新增 `expression.lua`（表达式校验）与 `solver.lua`（24点求解器）两个纯逻辑模块
